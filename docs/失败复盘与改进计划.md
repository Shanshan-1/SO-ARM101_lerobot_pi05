# π₀.₅ 真机抓取失败复盘与改进计划

## 1. 证据边界

- **已核实**：公开数据集包含 40 条示教、17,961 帧、两路相机；公开模型的训练配置记录 5,000 steps、batch size 8、`train_expert_only=true`、`freeze_vision_encoder=true`、`eval_split=0.0`、`eval_steps=0`。见[数据集元信息](https://huggingface.co/datasets/Shanshan777/lerobot_dataset_01_20261014_233057/blob/main/meta/info.json)和[模型训练配置](https://huggingface.co/Shanshan777/lerobot_pi05_01/blob/main/train_config.json)。
- **视频可见**：机械臂向目标区域运动，但这段约 17 秒的录像没有展示完成夹取与抬升；视频只代表一次失败样例。
- **项目反馈**：真机任务成功率几乎为 0，尚无公开的逐次评估表，不应写成精确成功率。
- **训练日志**：[W&B 项目页](https://forge.coreweave.com/wandb/1808025338-tinghua/pi05/overview)可能需要登录或权限；此文不引用无法核对的 loss 数值、训练时长或吞吐。

## 2. 排查假设与验证实验

| 优先级 | 假设与依据 | 最小验证实验 | 如何判定 |
| --- | --- | --- | --- |
| P0 | **相机／预处理不一致**：基础模型声明三路相机槽位，微调模型是 `front`、`wrist` 两路；操作手册还指出远程推理可能把 4:3 图像直接拉伸到 224 × 224。 | 保存训练数据样本与推理时送入模型的两路图像，对照相机语义、顺序、尺寸、补边和颜色；确认是否使用远程推理客户端及其预处理。 | 两端同一场景的模型输入应有一致的几何变换和相机含义；修正前后在相同测试集比较。 |
| P0 | **动作和标定链偏差**：视频中接近目标却未抓起，可能涉及夹爪方向、动作尺度、初始姿态或坐标定义。 | 检查 checkpoint 随附的 pre/postprocessor 与归一化统计量；在安全条件下逐关节验证动作方向、夹爪开合，再回放一条示教动作。 | 若示教动作本身无法稳定完成同任务，先修控制或标定，不重训模型。 |
| P1 | **示教覆盖不足**：40 条同一任务、约 10 分钟示教，起点与物体位置变化可能不足。 | 将失败初始场景与 40 条示教的起点、目标位置和两路画面并排比较；补采变化后的示教。 | 补数据后的留出集和真机成功率在相同场景上改善，才支持该解释。 |
| P1 | **微调范围受限**：`train_expert_only=true` 且 `freeze_vision_encoder=true`，视觉特征未针对现场重新训练。 | 在相同数据与评估条件下，与其他可在显存内运行的微调范围或视觉输入策略对照。 | 只在成功率有稳定提升时扩大训练范围，避免凭训练 loss 判断。 |
| P2 | **动作块过长**：配置为 `n_action_steps=50`，30 fps 下对应约 1.7 秒动作。 | 在不改变其他条件的情况下，比较短动作块／更频繁重规划与 50 步设置。 | 记录接近、夹取、抬升三个阶段的成功率和控制时延。 |

**注意**：`rename_map={}` 与两路相机配置是已核实的事实，但模型也可能按该配置正确训练和推理；仅凭配置差异不能判定具体故障。预处理问题同样需要先确认本次是否使用了手册描述的远程推理路径。

## 3. 下一轮实验顺序

1. **冻结当前版本**：保存模型 commit、数据集版本、LeRobot 版本、相机编号、标定文件和推理命令；录制两路相机原图及送入模型的处理后图像。
2. **先做无模型基线**：回放示教轨迹，确认机械臂、夹爪与任务场景本身能完成抓取；若失败，优先修复硬件／标定／动作映射。
3. **建立评估表**：固定物体与机械臂起始条件，至少 20 次测试；逐次记下“接近／夹住／抬起／完成”，以“夹住并抬起目标”为主成功判据。保持相同条件比较各实验组。
4. **一项一项排查**：先对齐相机和预处理，再检查动作尺度与夹爪，之后才改变数据量和训练配置。每次只改一个主要变量。
5. **补数据与验证集**：覆盖不同位置、姿态、背景和光照；按 episode 切分训练／验证；在多个 checkpoint 上比较留出集指标与真机成功率。
